Saya ingin mengembangkan sebuah aplikasi Android eksperimental bertema **jokeware / nuisanceware** menggunakan **Antigravity IDE** sebagai lingkungan pengembangan utama dan **terminal dengan Gradle CLI** untuk proses build, install, dan debugging.

Jangan menggunakan Android Studio sebagai IDE atau bagian dari workflow pengembangan.

---

# 2. KONSEP APLIKASI

Saya sedang membuat aplikasi eksperimental bertema:

**Jokeware / Nuisanceware**

Tujuan aplikasi bukan mencuri data atau merusak sistem.

Aplikasi berfokus pada efek prank yang mengganggu pengguna melalui perilaku audio/volume.

Tidak boleh ada:

* pencurian data;
* credential stealing;
* keylogging;
* penghapusan file;
* modifikasi file pengguna;
* ransomware;
* enkripsi data;
* spyware;
* pengiriman data ke server;
* persistence tersembunyi;
* privilege escalation;
* exploit;
* root;
* atau mekanisme untuk mengambil alih seluruh perangkat.

---

# 3. KONSEP UTAMA APLIKASI

Ketika user membuka aplikasi:

```text
OPEN APPLICATION
        ↓
Activity berjalan
        ↓
UI benar-benar transparan
        ↓
Tidak ada elemen UI yang terlihat
        ↓
Volume media diarahkan ke maksimum
        ↓
Efek prank aktif
```

Aplikasi harus terasa seperti:

> "Tidak ada apa-apa di layar."

Bukan sekadar tampilan minimal.

Background Activity harus benar-benar transparan sehingga konten di belakang Activity tetap terlihat.

Activity harus menggunakan **100% transparent window**.

Jangan menggunakan:

* background hitam;
* background putih;
* semi-transparent overlay;

* card;
* toolbar;
* splash screen yang terlihat;
* teks;

* menu;
* dialog;
* atau elemen visual lainnya.

Saat aplikasi aktif, user harus hampir tidak menyadari bahwa sebuah Activity sedang berjalan.

Tidak boleh ada:

```text
STOP PRANK
EXIT
CLOSE
CANCEL
```

atau tombol penghentian di dalam UI.

# 5. PERILAKU SAAT APLIKASI DIBUKA

Saat Activity pertama kali dibuat:

1. Simpan nilai volume media saat ini.
2. Inisialisasi controller prank.
3. Naikkan volume media ke level maksimum yang diperbolehkan Android.
4. Jalankan efek audio jika diperlukan.
5. Jangan meminta akses terhadap data pengguna.
6. Jangan melakukan network request.
7. Jangan menjalankan proses persistence.

Fokus hanya pada:

**Media Volume**

Jangan mengubah:

* ringtone volume;
* notification volume;
* alarm volume;

kecuali memang diperlukan secara eksplisit oleh implementasi Android dan dijelaskan terlebih dahulu.

---

# 6. PERILAKU PERANGKAT

Walaupun prank aktif, perangkat tetap harus dapat digunakan.

User tetap dapat:

* menggunakan touchscreen;
* membuka aplikasi lain;
* membuka Home;
* membuka notification panel;
* menggunakan Back;
* mengunci layar;
* melakukan aktivitas Android normal.

Aplikasi tidak boleh:

* mengunci touchscreen;
* mengunci seluruh perangkat;
* membuat kiosk mode;
* mencegah user membuka aplikasi lain;
* mencegah user melakukan restart;
* mengambil alih seluruh sistem.

---

# 7. TOMBOL VOLUME

Konsep prank yang diinginkan:

> volume terlihat seperti terkunci pada level maksimum.

Namun implementasikan hanya menggunakan kemampuan API Android yang tersedia untuk aplikasi biasa.

Jangan melakukan bypass terhadap Android untuk benar-benar memblokir tombol volume.

Jangan menggunakan:

* Accessibility Service untuk mengambil alih tombol;
* Device Administrator;
* root;
* exploit;
* system privilege;
* custom ROM;
* input hijacking;
* atau mekanisme lain untuk mengambil alih kontrol sistem.

Jika Android tidak mengizinkan aplikasi biasa mempertahankan volume maksimum setelah user menekan tombol volume, jangan mencoba melewati pembatasan tersebut.

Dalam kondisi tersebut, jelaskan keterbatasannya dan implementasikan simulasi yang paling dekat dengan konsep prank.

---

# 8. HOME / BACKGROUND BEHAVIOR

Ketika user menekan Home dan Activity kehilangan foreground:

* hentikan efek prank;
* hentikan audio;
* lakukan cleanup;
* jangan menjalankan background persistence;
* jangan auto-start kembali.

Tidak boleh ada:

```text
BOOT COMPLETED
AUTO START
BACKGROUND SERVICE
HIDDEN SERVICE
SCHEDULED RESTART
```

Prank hanya aktif ketika user secara eksplisit membuka aplikasi.

---

# 9. RECOVERY VOLUME

Bagian ini sangat penting.

Sebelum prank dimulai:

```text
originalVolume = currentMediaVolume
```

Ketika prank aktif:

```text
currentMediaVolume → maximum
```

Ketika aplikasi berhenti:

```text
maximum → originalVolume
```

Contoh:

```text
Volume sebelum aplikasi:
30%

Aplikasi dibuka:
30% → 100%

Aplikasi ditutup:
100% → 30%
```

Nilai volume awal hanya digunakan untuk recovery sesi tersebut.

Jangan menyimpan konfigurasi volume secara permanen.

---

# 10. LIFECYCLE

Gunakan Android Activity Lifecycle dengan benar.

Handle minimal:

```text
onCreate()
onStart()
onResume()
onPause()
onStop()
onDestroy()
```

Ketika Activity berhenti atau tidak lagi aktif, lakukan cleanup sesuai lifecycle.

Cleanup harus:

* menghentikan audio;
* membatalkan coroutine/timer;
* melepaskan resource;
* menghentikan controller;
* mengembalikan volume;
* memastikan tidak ada task tersembunyi yang tetap berjalan.

Hindari logic yang dapat menyebabkan:

```text
Activity → Service → Activity → Service → ...
```

atau loop background.

---

# 11. AUDIO

Jika aplikasi menggunakan efek suara:

* audio harus berasal dari resource aplikasi;
* jangan menggunakan microphone;
* jangan melakukan recording;
* jangan membaca audio pribadi pengguna;
* jangan melakukan streaming audio dari internet;
* hentikan audio ketika prank berhenti.

Gunakan audio player Android yang sesuai.

# 17. GRADLE CLI WORKFLOW

Seluruh proses build dilakukan melalui terminal.

Untuk Windows:

```powershell
.\gradlew.bat assembleDebug
```

Untuk sistem Unix:

```bash
./gradlew assembleDebug
```

Jika berhasil, APK berada di:

```text
app/build/outputs/apk/debug/app-debug.apk
```

Untuk membersihkan project:

```powershell
.\gradlew.bat clean
```

Untuk build dengan informasi error:

```powershell
.\gradlew.bat assembleDebug --stacktrace
```

Untuk mengecek task Gradle:

```powershell
.\gradlew.bat tasks
```

# 18. ADB DEPLOYMENT

Gunakan ADB dari terminal.

adb install -r app\build\outputs\apk\debug\app-debug.apk

```powershell
adb uninstall [package-name]
```
